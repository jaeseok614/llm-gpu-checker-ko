# v7.12.0 — MLX 실행 방식 추가 (Apple Silicon 전용)

## 이번 릴리스

사용자가 "추론 엔진이 vLLM/Ollama/llama.cpp뿐인 것 같다"고 지적해, MLX(Apple의 Apple Silicon 전용 추론 엔진)를 4번째 실행 방식으로 추가했습니다.

- **신규 실행 방식:** "실행 방식" 선택지에 MLX(mlx-lm)를 추가했습니다. Apple GPU(M2/M3/M4 Max/Ultra 5종)를 선택했을 때만 나타나며, 다른 제조사 GPU를 선택하면 자동으로 llama.cpp/Ollama로 되돌아갑니다.
- **속도 배율의 근거:** 자체 벤치마크를 만들지 않고, local-llm.net의 공개 비교표(M4 Max 64GB·M3 Pro 36GB, llama.cpp Q4_K_M vs MLX 4bit, 2026-08 확인)를 유일한 근거로 삼았습니다. 실측 구간은 3-8B 모델 +3~8%, 12-14B 모델 +14~25%였으나, 실제 적용한 배율은 이보다 보수적으로 반올림한 계단식(+5%~+15%, 17B+ 모델은 +12%로 재수렴)입니다. 70B 모델에서 관측된 대폭 차이는 llama.cpp가 OOM으로 아예 못 돌아가는 상황(속도가 아니라 적합 여부의 문제)이라 이 배율에 반영하지 않았습니다.
- **첫 토큰 지연(TTFT):** 위 출처에 TTFT 관련 수치가 없어, 임의로 만들지 않고 llama.cpp와 동일(배율 1, 중립)로 두었습니다.
- **메모리 오버헤드:** 같은 출처의 메모리 사용량 비교(모델 크기별로 MLX가 총 메모리 5~10% 절약)를 참고해 MLX 런타임 오버헤드를 llama.cpp보다 다소 낮게 설정했습니다. 가중치 용량(weightsGb) 자체는 사용자가 고른 양자화 등급에 그대로 연동되므로 건드리지 않았습니다.
- **실행 명령어:** `mlx_lm.generate` 예시 명령어를 Apple GPU 선택 시에만 추가했습니다. MLX 저장소는 llama.cpp의 세분화된 K-quant 등급 대신 4bit/8bit/bf16만 흔히 배포하므로, 선택한 양자화 등급의 비트수를 가장 가까운 MLX 태그로 매핑했습니다.
- **GUI 앱 호환 안내(리스크 없는 추가):** LM Studio·koboldcpp·text-generation-webui는 모두 내부적으로 llama.cpp 엔진을 쓰므로 위 "llama.cpp / Ollama" 수치와 동일하다는 안내를 실행 방식 설정과 실행 명령어 화면 두 곳에 추가했습니다. 계산 로직은 전혀 바꾸지 않았습니다.

## 반영하지 않은 것

같은 대화에서 논의된 FreeToken(CPU+GPU 하이브리드 서빙 엔진, arXiv:2608.16157)의 정성적 호환 배지와 Unsloth Dynamic 양자화 옵션은 이번 릴리스에 포함하지 않았습니다. 둘 다 사용자의 명시적 확인을 받지 않았고, 특히 Unsloth Dynamic 양자화는 모델마다 압축률이 달라 이 프로젝트의 "양자화 등급 하나당 고정 배율 하나" 구조와 근본적으로 맞지 않아 신중한 검토가 더 필요합니다.

모든 속도 배율은 참고용 근사치이며, 실제 성능은 모델·컨텍스트 길이·macOS 버전에 따라 달라질 수 있습니다.
