# v7.0.0 — Decision-ready sizing and a 60-second tour

v7.0 focuses on making the existing depth easier to evaluate before public promotion.

## What changed

- A visible 60-second tour opens three complete examples without requiring initial input: an owned RTX 3060, a Qwen 32B GPU search, and a 30-user internal RAG estimate.
- A structured workflow feedback form asks what the user tried to decide and what remained confusing, while warning against sharing confidential data.
- Korean price coverage now separates sourced, fresh, aging, stale, and missing rows. Market rows are validated for duplicate GPU IDs, positive amounts, dates, and HTTPS sources.
- KRW/USD display, confidence labels, and used-price-method labels use shared locale helpers so repeated Korean–English switching does not expose mixed text.
- Economy, recommended, and scalable cards show only first-decision metrics. QPS, batching, queue state, reserve GPUs, exclusions, and PoC actions appear after selecting a plan.
- Core application, infrastructure, and stylesheet size budgets prevent accidental growth. Larger decision and infrastructure workspaces remain lazy-loaded.
- Calculation regressions run as five parallel GitHub Actions jobs, avoiding the previous single-job time and memory pressure while preserving the same test coverage.

## Reliability boundaries

Pricing and the KRW/USD exchange rate are editable planning assumptions, not live quotes. Throughput without matching measurements is shown as a range with an expected error. Procurement still requires a supplier quote and representative workload PoC.
